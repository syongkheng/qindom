# qindom — Project Mindmap

Express 5 + TypeScript + MySQL (db `wuxi`) via Knex. Native ESM (`"type": "module"`, `nodenext`, relative imports need `.js`). Dev runner: `tsx watch`. Deploy: AWS EC2 ap-southeast-1, port 3000, PM2 (`ecosystem.config.cjs`) behind nginx, behind Cloudflare (since 2026-11-19).

## Infrastructure

- DNS: `awense.com` zone on Cloudflare (free plan; registrar still Vercel). `api` A → EC2 `52.220.202.154` **proxied**; `@` and `www` CNAME → Vercel (`vercel-dns-017.com`) **DNS only** (Vercel advises against proxying). Universal edge cert covers `awense.com` + `*.awense.com`; SSL/TLS mode Automatic.
- Network: EC2 security group inbound = HTTP 80 + HTTPS 443 from managed prefix list `pl-0c867e2053ac61bf6` (`cloudflare-ipv4`, the 15 ranges from cloudflare.com/ips-v4), SSH 22 from the owner's IP only (if it changes, reset the rule to "My IP" or `deploy.sh` times out). Direct hits on the EC2 IP time out. If Cloudflare publishes new ranges, update both the prefix list and the nginx realip file.
- nginx proxies to :3000 and sets `X-Real-IP $remote_addr`. `/etc/nginx/conf.d/cloudflare-realip.conf` has `set_real_ip_from` for every Cloudflare v4/v6 range + `real_ip_header CF-Connecting-IP`, so `$remote_addr` (and therefore `X-Real-IP`) is the real client IP, not a Cloudflare edge IP.
- Origin TLS: certbot Let's Encrypt cert for `api.awense.com`; renewal works through Cloudflare (`certbot renew --dry-run` passed 2026-11-19).
- nginx `location /` already forwards `Upgrade`/`Connection` with HTTP/1.1 (WebSockets work, checked 2026-11-14 and through Cloudflare 2026-11-19); default 60 s `proxy_read_timeout` (Cloudflare idle limit 100 s), so long-lived sockets must ping (camera relay: 25 s).
- Deps: express ^5.1 (5.2.1), sharp 0.35.5, knex ^3.1, node-telegram-bot-api ^1.1, TypeScript ^5.9. `npm audit` clean as of 2026-10-07.
- Envs: Dev `.env.dev` · Prod `.env`, `NODE_ENV=prd` (PM2 `--env prd`). Loaded only by `src/config/loadEnv.ts`, the first import of `index.ts` (`override: true`); `npm run migrate` (`knexfile.ts`) and deploy's `src/migrate.js` deliberately load `.env` (prod) with plain `dotenv.config()`; tests load no env file. See `src/config/README.md`. Telegram bot (`tgimage/TgImage.bot.ts`) uses polling in both (no webhook), so it only makes outbound calls and is unaffected by Cloudflare or the security group.
- `postinstall`: `scripts/apply-patches.js` applies `patches/*.patch`; deploy.sh doesn't ship `scripts/`/`patches/`, so patches never apply on EC2.
- `deploy.sh`: rsync of `dist/` excludes `node_modules`, `.env`, `serviceAccountKey.json`, `logs`, `package*.json`, `.lock.sha` so `--delete` doesn't wipe them on EC2; deps reinstall only when `package-lock.json` sha differs from `.lock.sha`; after PM2 start it polls `localhost:3000/connectivity` (15×2s) and exits non-zero with PM2 logs if unhealthy.
- Knex CLI scripts run via `node --import tsx`; `__dirname` via `fileURLToPath(import.meta.url)`.

## Middleware stack (global → route-level)

1. **CORS** (`ALLOWED_ORIGINS`, `config/cors.ts`; methods `GET,POST,OPTIONS` (DELETE dropped 2026-11-26); boot fails if `ALLOWED_ORIGINS` is empty/blank; foreign origin → registry `ForbiddenAccess` 403), security headers (nosniff, X-Frame DENY, no-referrer, HSTS in prd).
2. **globalLimiter** 100 req/min/IP. All limiters (`RateLimiter.ts`, one `limiter({...})` factory; table in `src/middlewares/README.md`) key on `X-Real-IP` (set by nginx; no `trust proxy`). Safe because port 3000 is reachable only via nginx, nginx only via Cloudflare (security group), and nginx's realip config takes the client IP from `CF-Connecting-IP` only when the connection comes from a Cloudflare range. If that realip file is removed, users share buckets per Cloudflare edge IP.
3. cookieParser, `express.json` 5MB, urlencoded.
4. **RestRequestLogger** — per-request log tree (IP via the shared `clientIp(req)` in `utils/RequestUtilities.ts`: X-Real-IP → socket → `"Unknown"`, used by every module that records an IP; the `finish` flush catches and logs its own failures) (stages: middleware → controller → service), console + request-log file (`RequestLogFileWriter`, 50MB rotation; prd `/home/ubuntu/.pm2/logs/qindom-request-tree.log`, dev `./logs/`). Telegram alerts: compact access-log line + link to fndom `/admin/log-searcher?requestId=…`. Suppression of non-error traffic only (4xx/5xx always alert) via hardcoded `TELEGRAM_SILENT_ROUTES` and per-(chat, module) toggles in `tb_telegram_log_subscription` (fan-out to every active `tb_tg_stats_whitelist` chat; admin matrix at fndom `/admin/telegram-log-subscriptions`, SYSTEM_R5, module list comes from the server; 30s cache; module key via `TelegramLogModules.ts`, which covers every Express prefix in app.ts (test-enforced; `house` = `/house-layout` + `/house`). Transport `utils/logging/TelegramLogSender.ts` → shared `sendTelegramHtml` (`utils/TelegramUtilities.ts`, also used by the wedding visit notifier); a failed send is a console warning only).
5. **Redaction** (`LogRedaction.ts`) by field name: passwords, tokens/jwt/secret, apiKey, otp/pin/verify_code/captcha, smsBody, authorization/cookie, blob; `code` only if OTP-shaped, `key` only if API-key-shaped; emails masked; regex pass on free text.
6. **RequestHeaderFilter** — `User-Agent` required (400 `invalid_request_user-agent`); POST needs `Content-Type: application/json` (415 `unsupported_media_type`, so bodyless POSTs send `{}`). Thrown, answered by ErrorHandler.
7. **MandatoryTokenFilter / OptionalTokenFilter** (`TokenFilter.ts`) — JWT in httpOnly cookie `jwt_token` (HS256 pinned, 30d; sign/verify + `JWT_ALGORITHM`/`JWT_TTL_MS` only in `src/token/Token.service.ts`, boot fails if `JWT_SECRET` missing), token compared to `tb_aa_user.token` (revocation; Optional drops to visitor on mismatch), roles read from DB row not JWT, double-submit CSRF (`csrf_token` cookie == `X-CSRF-Token` header on non-GET, byte lengths compared then timing-safe; mismatch 403 `csrf_invalid` in both). A failed session lookup (DB down) → 500 in both filters, not 401/visitor (fndom only logs out on 401 + `token_invalid`). Cookies scoped `.awense.com` in prd (`AuthCookieUtilities.ts`).
8. **RequestApiKeyFilter(...prefixes)** — `x-api-key` → `tb_ss_api_key` hash lookup; only the `ss_` prefix remains (`mw.ssKey` → `/v1/ss`, `/v2/ss`). MCP server + `mcp_` keys removed Nov 2026 (`tb_mcp_api_key` dropped by migration 20261126000000). The owner's `tb_aa_user` row must be active (a soft-deleted owner = invalid key). Key format exactly `<prefix>_<hex>` (extra `_` segments = invalid key). Any key failure → plain-string 401 (Shortcuts contract); a DB failure → 500; the raw key is not kept on the log context. `TokenOrApiKeyFilter.ts` unused (deletion pending). IoT routes removed Oct 2026 (redaction still masks `iot_` keys).
9. **404 catch-all** — after the route table, unmatched paths get the registry `Exceptions.NotFound` body (`status: "EntityNotFoundException"`, `data.code: "entity_not_found"`, message "Route not found"; no Express "Cannot GET" HTML). Unknown prefixes aren't logged/alerted; unknown paths under a mounted prefix go through that prefix's request log.
10. **ErrorHandler** — registered last; replaces Express default (no stack leaks). `BaseException` → status, Multer → 413/400, http-errors → 4xx, else generic 500.
11. **Crash guard** (`config/crashGuard.ts`, installed first thing in `index.ts`) — process-level `uncaughtException` / `unhandledRejection` are logged to PM2 (`crashGuard` tag + stack) and the process keeps running; boot failures still exit 1. Trade-off in `src/config/README.md`.

## Modules

- **AUTH `/auth`** — register → OTP email → verify → JWT set via Set-Cookie only (never in body). `POST /logout` clears cookies; `POST /verification` reads cookie. bcrypt 10 rounds; OTP SHA-256, 15-min TTL, max 5 attempts (429). `/verify-email` requires `password` too (bcrypt-checked; wrong password counts as an attempt) so a pre-registered squat can't be verified by the real owner. Unverified rows whose OTP lapsed count as free: preflight says register, register soft-deletes them (email or username). Register `system` must be in `REGISTER_SYSTEMS` (`["fnd"]`). Limits: preflight 30/15min/IP, 5 reg/hr, 10 login/15min, verify 10/15min, resend 3/15min; password validate+update share `passwordCheckLimiter` 10 failures/15min per user (a wrong password on validate answers 200 `{isValid:false}` but is flagged with `countAsFailedAttempt`). Caps: email 255, system 256, username 3–64 chars, password ≤ 72 UTF-8 bytes (bcrypt; new → `weak_password`, existing → `invalid_request_<field>`). OTP `crypto.randomInt`. Password-changed email has no timestamp. PM2 lines mask emails (`maskEmail` / `maskEmailsInText` in `LogRedaction.ts`, applied by `LoggingUtilities.service.*`). Usernames HTML-escaped in emails. **Dev OTP bypass:** code `111111` accepted only when `IS_DEV` (`NODE_ENV === "dev"`; injectable `devOtpBypass` for tests). Admin (`AuthAdmin.controller.ts`, mounted at `/auth/admin`, `requireRole(OWNER)` → 403 `forbidden_access`): users list / `POST /admin/users/:id/roles` (missing or soft-deleted user → 404; removing your own `SYSTEM_R5` → 403), `GET /admin/recent-request-logs?limit=`, `GET /admin/request-logs/:requestId` (`req_` + 12 hex; older 5-hex ids accepted; parsed by `utils/logging/RequestLogParser.ts`, must track `LoggingUtilities.render()`), Telegram log-subscription matrix. Services split: `AuthRegistration` (preflight/register/verify/resend), `AuthSession` (login, `issueSession`, logout revocation, password), `AuthAdmin`; emails from pure builders in `Auth.emailTemplate.ts`; see `src/auth/README.md`. DB: `tb_aa_user` (unique `username_system_active` among active rows).

## DB patterns

- Soft delete `record_status` 'A'/'D'; **soft-deleted = gone** in code (above all users: lookups, joins, access checks and lists filter on active rows; writes target `{ id, record_status: 'A' }`); timestamps are ms epoch (`Date.now()`); JSON fields (roles, pax_names…) stored as strings; audit `created_by`/`updated_by` (username).
- Never put plain UNIQUE on a user-chosen value (a 'D' row would block a new one): use a VIRTUAL column `IF(record_status='A', col, NULL)` + UNIQUE. System ids (uuid, session_id, short_code) stay plain UNIQUE.
- `KnexSqlUtilities` takes an optional log event (last param) and adds timed SQL lines to it; all raw SQL uses bindings. `transaction(cb, event?)` hands the callback `(trx, tx)`: the raw knex trx and a `KnexSqlUtilities` bound to it (use `tx.insert/insertId/insertMany/update/updateCount/updateCountIn/find…(…, event)` so statements are timed; no call site uses the raw trx since the itinerary save moved to `tx`, Nov 2026). A `BaseException` thrown inside is rethrown unchanged (keeps its 4xx); other errors become a plain `Error` (500) with `cause` kept, which the request tree shows as `(cause: Error ER_…)`. `updateCount` = UPDATE without the re-read, returns affected rows; `updateCountIn` adds `AND col IN (…)`; `insertId` = INSERT returning the id (no re-read); `insertMany` = one multi-row INSERT.
- DECIMAL columns come back from mysql2 as strings: row types say `number | string`, mappers use `toDecimalNumber` (`utils/NumberUtilities.ts`) so the API always returns numbers (NULL → `null`, unreadable → `null` + PM2 warning). Agenda `duration_in_hours` / `budget` are numbers since Nov 2026 (were strings).
- Public uuids (`tb_budget_item.uuid`, `tb_applepay_transaction.uuid`) are NOT NULL since migration `20261126000400_make_public_uuids_not_null` (backfills NULLs with `UUID()` first). No hand-written schema file: the schema lives in `src/migrations` (`master.sql` copies deleted Nov 2026).

## Code conventions

- **Style guide: `docs/CODING_STYLE.md`** (source of truth; refactor progress in `docs/REFACTOR_CHECKLIST.md`). Prettier (`npm run format`).
- Response interfaces `XyzDto` + request bodies `XyzBody` → co-located `src/<module>/<Module>.types.ts` (`models/dtos/` + `models/requests/` are gone). DB rows → `models/databases/tb_<table>.ts` exporting `ITB_<TABLE>` (file and interface named after the table; `record_status: RecordStatus`; NULL columns `| null`; BIGINT ms `number`). `src/models/` also keeps the shared `IRequestLogContext` and `ControllerResponse`; the session payload `IDecodedTokenUser` lives in `token/Token.types.ts`. See `src/models/README.md`.
- URLs use hyphens. Envelope `{ code, status: "Ok"|"Ko", data }`.
- Env flags: `APP_ENV`/`IS_PRD`/`IS_DEV` from `src/config/env.ts`. Only `config/loadEnv.ts` (first import of `index.ts`) and `migrate.ts`/`knexfile.ts` load dotenv (test-enforced); knex reads `DB_*` on first connection via `config/db/connection.ts` `readDbConnection()`; `utils` reads dotenv values lazily (mail transporter built on first send, Telegram token via `getTelegramBotToken()`). Shared constants in `src/constants/` (`RecordStatus`, `Time`, `APP_TIMEZONE`, `DEFAULT_CURRENCY`, `LogEmoji`). Role guard: `requireRole(req, ...roles)` throws ForbiddenAccess.
- Shared helpers in `src/utils/` (see its README): `RequestUtilities` (`route`, `getUser`, `getApiKeyUserId`, `requireRole`, `clientIp`, `handleException`), `ErrorUtilities` (`toMessage`), `StructuralValidationUtilities` (`V.*`; `requiredText`/`optionalText` count code points like utf8mb4), `NumberUtilities` (`toDecimalNumber`), `KnexSqlUtilities`, `TelegramUtilities`, `MailerUtilities`, `AuthCookieUtilities`, `HashUtilities`, `MaskingUtilities`.
- Controller factory `createXyzController(db)` → Router; handlers wrapped in `route(label, fallback, handler)` (`RequestUtilities`), which builds `cr` and calls `handleException` (migrating folder by folder). Role guard `hasRole(req, ...roles)` (`RequestUtilities`).
- Exceptions: all in `src/exceptions/AppExceptions.ts`, thrown via `Exceptions.X` (never return error strings; `code` + class name are an fndom contract); handlers wrapped in `route()` → `handleException(err, cr, label, fallback)`: `BaseException` → `cr.result(status, name, clientMessage)`, else log + `cr.ko(fallback)` (real cause kept in request tree).
- Logging: services take `logContext?: IRequestLogContext` (last), emit events via `LoggingUtilities.request.branch()` (accepts undefined context → returns undefined, no guards) (pending-event pattern: set `.detail` after the async result); controllers pass `req.logContext`.
